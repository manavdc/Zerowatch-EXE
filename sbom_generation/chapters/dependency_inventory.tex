\chapter[Dependency Inventory]{\IconBox\ Dependency Inventory}
\chaptermark{Dependency Inventory}

This chapter presents an inventory of software components identified in the generated Software Bill of Materials (SBOM). Each component is uniquely identified by its package name, version, component type, software license, and Package URL (PURL).

The dependency inventory serves as the authoritative record of third-party software incorporated into the \textbf{\ProjectName} application. It provides the foundation for vulnerability assessment, license compliance, software supply chain analysis, and continuous Software Composition Analysis (SCA).

The generated inventory was subsequently analyzed using Grype and the ZeroWatch Agent Scan to correlate software components with publicly disclosed security vulnerabilities and available remediation information.

\section{Component Identification}

Each component in the SBOM is uniquely identified using the following attributes:
\begin{itemize}
\item Package Name
\item Version
\item Component Type
\item Software License
\item Package URL (PURL)
\item Supplier Information (where available)
\item Dependency Relationships
\item Vulnerability Correlation (through Grype and ZeroWatch Audit Scan analysis)
\item Security Advisory References (where applicable)
\end{itemize}

\section{Purpose of the Inventory}

Maintaining an accurate dependency inventory enables organizations to:
\begin{itemize}
\item Track every third-party software component.
\item Perform Software Composition Analysis (SCA).
\item Correlate software components with known vulnerabilities.
\item Detect outdated or unsupported packages.
\item Monitor dependency changes across software releases.
\item Simplify software license compliance.
\item Improve software supply chain transparency.
\item Support vulnerability management and remediation.
\item Assist incident response and forensic investigations.
\end{itemize}

\section{Complete Inventory}

The complete dependency inventory consists of all \TotalComponents\ software components identified during SBOM generation using Syft. The inventory is maintained in the original CycloneDX SBOM and may also be exported in CSV or spreadsheet format for automated processing, reporting, and audit purposes.

The generated inventory serves as the primary input for the Grype and ZeroWatch Agent Software Composition Analysis (SCA) scans, which evaluate each identified component against multiple vulnerability databases to detect known security issues and available software updates.

\section{Summary}

The dependency inventory provides a comprehensive record of all software components used by the \textbf{\ProjectName}. Combined with the metadata, license analysis, dependency analysis, and Grype/ZeroWatch Agent vulnerability assessments, this inventory establishes a complete view of the application's software supply chain.

Maintaining an accurate and continuously updated dependency inventory enables effective Software Composition Analysis (SCA), strengthens software supply chain security, simplifies compliance activities, and supports proactive vulnerability management throughout the software development lifecycle.
