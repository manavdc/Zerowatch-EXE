# Headless / Silent Command-Line Enrollment Specification

**Document Version:** 1.0  
**Target:** ZeroWatch SentinelAgent (Windows, macOS, Linux)  
**Status:** Architecture Proposal for Engineering Leads Review  

---

## 1. Executive Summary & Problem Statement

### The Problem
Currently, the ZeroWatch Sentinel Agent requires an interactive GUI (Tkinter) session to complete initial device enrollment. If launched in headless daemon mode on an unlinked machine, the agent immediately exits with:
```
Daemon blocked: Consent not accepted yet and agent is not linked.
```

### The Enterprise Impact
Enterprise customers cannot deploy ZeroWatch across thousands of workstations and servers using standard Enterprise Mobility Management (EMM) or Unified Endpoint Management (UEM) tools, such as:
* **Microsoft Intune / SCCM** (Windows fleet deployment)
* **Jamf Pro / Kandji** (macOS corporate fleet management)
* **Ansible / Puppet / Chef / Terraform** (Linux cloud instances & data center servers)
* **Group Policy Objects (GPO)** (Active Directory domain rollouts)

All enterprise deployment tools execute software installers under non-interactive system service accounts (`NT AUTHORITY\SYSTEM` on Windows, `root` daemon on Linux/macOS) where no display server (`$DISPLAY` or WindowServer) exists.

---

## 2. Proposed CLI Command Syntax

### Unified Silent Enrollment Command
```bash
# Windows (PowerShell or cmd.exe running as Administrator / SYSTEM)
SentinelAgent.exe --enroll-silent --team-code "<TEAM_CODE>" [--server "<API_URL>"] [--accept-eula] [--asset-name "<OPTIONAL_NAME>"]

# Linux (Root / systemd installer script)
./zerowatch-agent-linux-x64 --enroll-silent --team-code "<TEAM_CODE>" [--server "<API_URL>"] [--accept-eula]

# macOS (Terminal running under sudo / Jamf policy)
sudo ./zerowatch-agent-macos --enroll-silent --team-code "<TEAM_CODE>" [--server "<API_URL>"] [--accept-eula]
```

## 3. Parameter Specifications

| Parameter | Type | Required | Description |
| :--- | :---: | :---: | :--- |
| `--enroll-silent` | Flag | **Yes** | Instructs the binary to execute headless enrollment and suppress all UI/dialog elements. |
| `--team-code` | String | **Yes** | The 6-to-12 character alphanumeric team code generated by the ZeroWatch web dashboard. |
| `--accept-eula` | Flag | **Yes** | Legally records that the deploying IT administrator has accepted the End User License Agreement and telemetry terms on behalf of the organization. |
| `--server` | String | Optional | Overrides backend API base URL (defaults to production `https://zerowatch.deepcytes.io`). |
| `--asset-name` | String | Optional | Custom name for the asset in the dashboard (defaults to machine hostname). |
| `--start-daemon` | Flag | Optional | Installs and activates background service immediately upon successful enrollment (default: `true`). |

## 4. Execution Workflow (Step-by-Step)

```
[ IT Deployment Script (Intune / Jamf / Ansible) ]
                    │
                    ▼
   [ Launch SentinelAgent with --enroll-silent ]
                    │
                    ▼
     Check Administrator / Root Privileges?
          ├── No  ──> Exit Code 10 (Access Denied / Elevation Required)
          └── Yes ──> Continue
                    │
                    ▼
      Verify Mandatory Parameters Present?
          ├── Missing --team-code ──> Exit Code 11 (Invalid Arguments)
          ├── Missing --accept-eula ──> Exit Code 12 (EULA Consent Required)
          └── Valid ──> Continue
                    │
                    ▼
     Collect System Fingerprint (MAC, BIOS, GUID)
                    │
                    ▼
   Submit Enrollment Request to ZeroWatch Cloud
   POST /api/agent/join-team
          ├── Invalid Code / Expired ──> Exit Code 20 (Authentication Failed)
          ├── Network / Timeout / Pin Error ──> Exit Code 21 (Connection Failure)
          └── HTTP 200 (Success) ──> Continue
                    │
                    ▼
   Save Encrypted State to Native Secure Vault
   (DPAPI on Windows, Keychain on macOS, AES-GCM Vault on Linux)
                    │
                    ▼
   Write consent_accepted.dat with Admin Timestamp
                    │
                    ▼
   Register & Start Persistent Background Service
   (Windows Task / Service, systemd on Linux, launchd on macOS)
                    │
                    ▼
   Perform Immediate Initial Baseline Inventory Sync
                    │
                    ▼
   Exit Cleanly with Code 0 (Success)
```

## 5. Standardized Process Exit Codes

Enterprise deployment engines rely on numeric exit codes to report rollout success or failure in admin dashboards:

| Exit Code | Meaning | Remediation Action for IT Admin |
| :---: | :--- | :--- |
| **`0`** | **Success** | Device successfully enrolled and daemon active. |
| **`10`** | **Elevation Required** | Re-run package with administrative / root elevation. |
| **`11`** | **Missing Arguments** | Supply mandatory `--team-code` parameter. |
| **`12`** | **EULA Flag Required** | Add `--accept-eula` flag to deployment script. |
| **`20`** | **Invalid Team Code** | Verify team code in ZeroWatch web console. |
| **`21`** | **Network / TLS Error** | Check firewall, proxy, or SSL inspection settings. |
| **`22`** | **License Limit Exceeded** | Enterprise seat limit reached in tenant account. |
| **`30`** | **Vault Storage Error** | OS secure store failure (e.g. DPAPI or Keychain error). |

## 6. Security & Audit Trail Compliance

1. **Non-Interactive EULA Recording:**  
   When `--accept-eula` is passed, the agent records an immutable audit log entry in `consent_accepted.dat`:
   ```json
   {
       "consent_method": "silent_enterprise_deployment",
       "accepted_by_user": "SYSTEM",
       "timestamp": "2026-11-05T15:30:00Z",
       "team_code_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
   }
   ```
2. **Zero Plaintext Secrets:**  
   The team code argument is scrubbed from process memory immediately after the join request completes.
3. **Idempotent Execution:**  
   If an administrator accidentally runs the silent enrollment command on an already-enrolled machine, the agent checks `is_enrolled()`, validates the existing token, and exits with code `0` without creating duplicate devices in the dashboard.
